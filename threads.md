# X/Twitter launch threads

## Thread A — Problem → product → proof → ask

```
1/ Hook from hooks.md

2/ The painful workflow (3 bullets of how it sucked)

3/ What I shipped (one sentence + who it's for)

4/ What's inside (3–5 concrete deliverables)

5/ Price + why that price (anchor honestly)

6/ Early proof (screenshot, testimonial, or "N beta users")

7/ Link + soft CTA: "If this is useful, reply with your niche — I'll suggest a positioning line"
```

## Thread B — Teach then link

```
1/ Teach one sharp tip (no product yet)

2–5/ Steps / mistakes / examples (pure value)

6/ "I turned this into a template so I stop repeating myself"

7/ Link + "fork it / roast it"
```

## Thread C — Changelog launch

```
1/ v1 is live: [PRODUCT] for [AUDIENCE]

2/ v1 includes: …

3/ Deliberately NOT included yet: … (sets expectations)

4/ Roadmap next 2 weeks

5/ Link + ask for the #1 feature request
```

## Thread hygiene

- Number tweets `1/`, `2/` for clarity
- Put the URL in the last tweet (or reply) unless your audience expects it earlier
- Pin the thread; keep replying for 24h
- Don't thread-spam the same launch daily — post updates instead
